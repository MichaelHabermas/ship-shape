## Product And System Invariants

Things that should stay true across features, refactors, and fixes.

- Document Mutation Core (2026-05-24): generic document create/update/content/delete/convert routes now route through `api/src/services/document-mutations.ts`; future generic document write side effects should extend that boundary instead of adding route-local logic. Keep `DocumentPolicy` reason-coded and static-policy-table-first; do not jump to generated guards/probes until the matrix remains readable across more routes.
- Security Capability Core (2026-05-24): REST, files, setup, API tokens, and collaboration authorization now route through `api/src/security/principal.ts`, `tokens.ts`, and `capabilities.ts`. New sensitive surfaces should add a `Principal` + reason-coded `Capability` decision instead of route-local workspace/user checks. Existing API tokens retain `legacy:full`; newly created tokens are admin-created, scoped, and short-lived by default.
- File access rule after security closure: editor/document uploads should bind `files.document_id`; bound files authorize through the linked document, while legacy unbound files degrade to uploader/admin access.
- Collaboration security parity: WebSocket joins, periodic revalidation, room budgets, and Yjs history attribution should preserve the same capability model as REST. Do not add a realtime-only access path.
- Security findings closeout rule (2026-05-24): use the findings CLI plus mapped probe/focused test evidence before marking SS-FIND rows fixed. A code inspection alone is not enough. Current identity/token/file closeout proof is the focused API/security run covering workspaces/setup/api-tokens/files/openapi-contract/capabilities.
- Generic document delete is intentionally a creator/admin-only soft delete (`deleted_at`), not `DELETE FROM documents`; hard deletes erase children/history/snapshots through cascades and break retention/audit intent.
- Durable choices from audit/improvement work belong in `my-docs/DECISION_LOG.md`; keep `MEMORY.md` to short rules and traps, and use the decision log when a choice needs rationale, alternatives, consequences, and evidence.
- Type-safety work should prioritize runtime boundary typing: API route request/query parsing, PostgreSQL row-to-domain mappers, and document `properties` narrowing.
- Meaningful `as` cast cleanup should preserve a named boundary: API query coercion via schemas, persisted JSONB through guards, frontend response shaping through mappers, and status-bearing errors through `ApiStatusError`; do not scatter one-off assertions back into routes/pages.
- Week document properties are canonically only `sprint_number` and `owner_id`; route code may still read/write legacy plan/review fields, but type aliases should not present those fields as the source-of-truth week model.
- Tier 1 shared types (2026-05-22): import `InferredProjectStatus`, `SelectableDocumentType`, `ConversionDocumentType`, `ISSUE_STATE_OPTIONS`, `ISSUE_STATE_LABELS`, `BelongsTo`, and `ApiResponse` from `@ship/shared` — do not reintroduce local `BelongsToEntry`, `ApiEnvelope`, or shadow `DocumentType` unions for the same subsets. OpenAPI wire schema name `BelongsToEntry` is HTTP-only.

## Counterfeit Progress

Work that looks helpful but does not actually improve the system.

- Superficial `any` -> `unknown` changes without meaningful narrowing do not count as real type-safety improvement.
- Repeated local aliases that rename product concepts are a drift source, not harmless duplication. Keep SQL projection row types local, but derive durable document property/domain types from `@ship/shared`.
- Discovery reconciliation needs explicit status hygiene: resolved audit leads can stay as baseline history, but they should be marked resolved/retired and removed from active provisional candidate lists so future passes do not rediscover already-fixed work.
- Generated reviewer bundles and one-off orchestration plans are not source documentation. Keep source truth in the ledger, source-of-truth briefs, and durable narrative docs; regenerate deployable bundles from scripts instead of preserving stale copies in-tree.
