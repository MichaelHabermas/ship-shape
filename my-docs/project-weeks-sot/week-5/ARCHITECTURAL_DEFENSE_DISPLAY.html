FleetGraph Architectural Defense

Project drift, caught early.

FleetGraph is not a chatbot. It is a proactive drift operator inside Ship.

The MVP proves one hard loop: detect blocked committed work in an active sprint, create a contextual finding within 5 minutes, and stop at a human gate before consequences.

Simple rule: FleetGraph diagnoses. Humans approve consequences. Ship stays canonical.

The trigger changes. The reasoning system does not.

The graph branches by mode, eligibility, permissions, confidence, action risk, dedupe state, and whether the problem is still open. That is why this is not a straight pipeline.

The 5-Minute Promise

Polling is the MVP because reliability beats plumbing.

FleetGraph checks every 2 minutes. Empty checks are cheap SQL. The LLM runs only when deterministic checks find an eligible candidate.

0-2mWait for worker tick
30sFetch candidate context
60sRun graph reasoning
30s+Persist, show, retry buffer

Safety Boundary

Ship owns work. FleetGraph owns findings.

FleetGraph can do alone

  • Read permitted Ship data
  • Create, update, dedupe, and resolve findings
  • Explain evidence and draft a next action
  • Stay quiet when confidence or visibility is wrong

Human approval required

  • Assign work or change issue status
  • Move scope between sprints or weeks
  • Change priority
  • Post, message, notify, or escalate

Defense Script

Lead with the constraint, then the proof.

We are not building a general project assistant. We are building a proactive drift operator. The MVP proves Ship state can change without a user present, FleetGraph can notice, explain, and prepare action, and humans remain in control before anything affects Ship or people.

Decision 1Narrow detector first.
Decision 2Polling now, hybrid later.
