The 5-Minute Happy Path (the actual platform demo)

This is the "five-line developer story" turned into clicks you can watch in the browser.

1

Log in and open the Developer Portal

Open Developer Tab →

Proof: You are looking at the live self-service dashboard for the platform. This is what a real developer uses to manage their integration.
2

Create an OAuth app (secret shown once)

In the Developer tab: click Create app, give it a name, add a redirect URI (anything like https://example.com/callback works for demo), pick scopes documents:read documents:write webhooks:manage, submit.

Proof: The raw client secret appears exactly once in a big yellow box. Copy it. Refresh the page — it is gone forever. This proves gate 1 and the "shown once" UX.
3

Prove the SDK + PKCE flow (browser demo)

Open the SDK Demo page →

Paste the client_id from the app you just created. Click Connect. Approve the consent screen. After redirect you should see "Connected." and live lists of Documents and Issues loaded via the typed SDK.

Try the "Create" button to make a new document.

Proof: Full Authorization Code + PKCE completed in the browser. The SDK made authenticated calls to the public /api/v1 surface using the token it obtained. This proves gates 2 and 8 live.
4

Prove webhooks + delivery visibility (the Delivery Log "dashboard")

Back in the Developer tab, with your app selected:

  • Create a webhook subscription for document.created (pick any https:// webhook tester or just a placeholder — the log will still capture it).
  • Go to the main app (or use the SDK demo Create button) and create a new document.
  • Back in the Developer tab, look at the Delivery Log section (toggle "DLQ only" off). Refresh if needed.
Proof: You will see a new row for the event. It shows attempt, HTTP status, latency, idempotency key, and whether it was delivered. This is the live, queryable delivery log that every platform developer gets. Replays and DLQ are also right there with buttons.

Slack reference integration (visual proof): The separate reference integration (code in the repo) receives the exact same signed webhook and can post a message to a Slack channel. The platform side (signing + delivery) is proven in the log above. If a demo Slack channel is wired up for this reviewer session, you will also see the message appear in Slack.
